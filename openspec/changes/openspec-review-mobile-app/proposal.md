## Why

Командам нужен быстрый мобильный способ ревьюить OpenSpec-спецификации так же легко, как Anki-карточки, чтобы быстро находить спорные или некорректные требования прямо во время продуктового и технического анализа. Сейчас в проекте нет сценария, который превращает папку со `spec.md` файлами в последовательный review flow с историей решений, фильтрацией и процентной оценкой проблемных спецификаций.

## What Changes

- Добавить мобильный сценарий импорта коллекции OpenSpec-спецификаций из выбранной пользователем папки.
- Добавить review deck в стиле swipe cards, где каждая карточка представляет один Requirement и показывает название спецификации, краткое описание requirement, все связанные WHEN/THEN сценарии и полное описание requirement.
- Добавить сохранение истории свайпов, чтобы пользователь видел только еще не просмотренные карточки, пока не завершит текущий проход.
- Добавить post-review режим со статистикой по всей коллекции и по каждой спецификации, а также повторное ревью только отклоненных или только подтвержденных карточек.
- Добавить демо-коллекцию, доступную до первого импорта пользовательских спецификаций.
- Согласовать UX и визуальный язык приложения с референсами Figma и направлением Soft Consumer Minimalism.

## Capabilities

### New Capabilities
- `spec-library-ingestion`: импорт коллекции OpenSpec-папок, разбор `spec.md` файлов и нормализация Requirement/Scenario в карточки для ревью.
- `requirement-review-deck`: показ review-карточек со swipe-жестами, очередью непроверенных требований и карточным интерфейсом для мобильного сценария.
- `review-history-and-replay`: сохранение истории свайпов, исключение уже просмотренных карточек из активного прохода и запуск повторного ревью по выбранному фильтру.
- `review-analytics`: расчет общей и покомпонентной статистики по результатам ревью, включая долю требований, получивших отрицательный свайп.
- `demo-spec-bootstrap`: встроенная демо-спецификация, доступная пользователю до выбора собственной папки со спецификациями.

### Modified Capabilities

None.

## Impact

- Shared mobile UI в `composeApp/src/commonMain/kotlin` для deck, статистики, фильтров и экрана импорта.
- Парсинг markdown-спецификаций OpenSpec и преобразование структуры папок в доменные модели приложения.
- Локальное хранилище для импортированной коллекции, истории свайпов и агрегированной статистики.
- Интеграция с платформенными file picker API для выбора корневой папки спецификаций.
- Визуальная система приложения: мягкая минималистичная типографика, светлая палитра и карточный язык, вдохновленный Figma-референсами:
